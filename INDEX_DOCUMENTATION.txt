## 5️⃣ SOURCES DE DONNÉES

### 1. LOGS SYSTÈME
- **Fichier** : SystemLogs.tsx
- **Source API** : GET /api/audit-logs
- **Format** : Array of AuditLog
- **Réel?** : ✅ OUI (DB Audit Service)

### 2. HEALTH SERVICES
- **Fichier** : SystemMonitoringDashboard.tsx
- **Source API** : GET /actuator/health (ports 8080-8085)
- **Format** : JSON { status: "UP|DOWN|DEGRADED" }
- **Réel?** : ✅ OUI (Spring Boot Actuator)

### 3. CPU METRICS
- **Fichier** : SystemMonitoringDashboard.tsx
- **Source API** : GET /actuator/metrics/process.cpu.usage
- **Format** : JSON { measurements: [{value: 0-1}] }
- **Réel?** : ✅ OUI (Micrometer)

### 4. MEMORY METRICS
- **Fichier** : SystemMonitoringDashboard.tsx
- **Source API** : GET /actuator/metrics/jvm.memory.used
- **Format** : JSON { measurements: [{value: bytes}] }
- **Réel?** : ✅ OUI (Micrometer)

### 5. HTTP TRAFFIC
- **Fichier** : SystemMonitoringDashboard.tsx
- **Source API** : GET /actuator/metrics/http.server.requests.count
- **Format** : JSON { measurements: [{value: count}] }
- **Réel?** : ✅ OUI (Micrometer)

## ⚙️ CONFIGURATION REQUISE

Si les métriques ne s'affichent pas, ajouter à `application.properties` :

```properties
management.endpoints.web.exposure.include=health,info,metrics
management.endpoint.health.show-details=always
management.metrics.enable.jvm=true
```

## 📞 TROUBLESHOOTING RAPIDE

### Problème: "Aucun log n'apparaît"
→ Vérifier: `curl http://localhost:8080/api/audit-logs`
→ Création d'une action dans l'app? (employer, org, etc.)

### Problème: "Monitoring affiche DOWN"
→ Vérifier: `curl http://localhost:8080/actuator/health`
→ Service lancé? Actuator activé dans application.properties?

### Problème: "Graphiques vides"
→ Vérifier: `curl http://localhost:8080/actuator/metrics/process.cpu.usage`
→ Metrics activées dans application.properties?
